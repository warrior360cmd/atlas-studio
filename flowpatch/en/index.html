What you receive

  • Process contract: inputs, trigger, steps, outputs, exclusions, exception owner
  • Input validation: invalid data writes nothing
  • Durable state and business key: a submission sent twice is processed once
  • Outages: at most 3 attempts, then an exception queue; revoked access → operator action
  • Lost response on an unverifiable write → human review, never a blind re-write
  • Pause and resume; pausing never undoes what is already written
  • Backup, isolated restore (processing stopped), operator guide and written test report

Options, quoted separately. Another app, trigger or branch, history backfill, higher volume, recurring monitoring. Hosting and tool licences billed separately by their vendors.

FAQ

Do we need AI?

Rarely. Deterministic rules come first; AI is added only where it shows a real benefit.

What if a tool goes down?

The item waits, retries at most 3 times, then lands in the exception queue with the failed step and the error.

Who owns the automation?

You do: code or configuration, versions and guide are handed over; it runs in an environment in your name.
