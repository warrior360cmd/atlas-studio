Les webhooks expliqués simplement

Qu’est-ce qu’un webhook, en quoi il diffère d’une interrogation régulière, et les précautions à prendre : vérification, doublons, ordre et indisponibilité.

Un webhook est un message qu’une application envoie automatiquement à une autre quand un événement se produit : nouvelle commande, paiement reçu, formulaire rempli. Au lieu d’aller vérifier régulièrement s’il y a du nouveau, on est prévenu.

Webhook ou interrogation régulière ?

  • Interrogation régulière : votre automatisation demande toutes les X minutes « y a-t-il du nouveau ? ». Simple, mais avec un délai et des requêtes souvent inutiles.
  • Webhook : l’application prévient dès que l’événement se produit. Plus rapide, mais il faut un point de réception disponible.

Les précautions

  1. Vérifier l’origine : la plupart des services signent leurs webhooks. Votre automatisation doit vérifier cette signature pour s’assurer que le message vient bien du service attendu.
  2. Accepter les doublons : un même webhook peut arriver deux fois. L’automatisation doit le reconnaître et ne pas le traiter deux fois ; voir reprise sur erreur.
  3. Ne pas compter sur l’ordre : deux événements peuvent arriver dans le désordre.
  4. Répondre vite : le service émetteur attend en général une réponse rapide ; un traitement long doit se faire ensuite.
  5. Prévoir l’indisponibilité : si votre point de réception est indisponible, le service réessaiera généralement pendant un temps limité. Au-delà, l’événement peut être perdu.

Un filet de sécurité

Pour les processus importants, combinez webhook et vérification périodique : le webhook pour la rapidité, une vérification régulière pour rattraper ce qui aurait été manqué.

Dans les outils sans code
