Limites d’API et quotas : éviter les blocages

Comprendre les limites de requêtes des API utilisées par vos automatisations, les erreurs qu’elles provoquent et comment les respecter sans perdre de données.

Les applications que relient vos automatisations limitent le nombre de requêtes qu’on peut leur envoyer dans un temps donné. Dépasser ces limites provoque des erreurs, parfois des blocages temporaires. Une automatisation fiable en tient compte.

Les limites courantes

  • Par minute ou par seconde : un nombre maximal de requêtes sur une courte période.
  • Par jour ou par mois : un quota global, parfois lié à votre formule d’abonnement.
  • Par opération : certaines actions coûteuses ont leur propre limite.

Ces limites sont indiquées dans la documentation de chaque service ; elles changent avec le temps et selon les formules.

Les signes d’un dépassement

Une erreur indiquant « trop de requêtes » (souvent le code 429), des réponses refusées en série, une automatisation qui ralentit fortement en fin de mois.

Comment les respecter

  1. Espacer les requêtes plutôt que de tout envoyer d’un coup.
  2. Réessayer avec un délai croissant après une erreur de limite, au lieu de réessayer immédiatement.
  3. Regrouper quand l’API propose des opérations par lots.
  4. Éviter les requêtes inutiles : préférer les webhooks à l’interrogation constante ; voir les webhooks.
  5. Mémoriser les informations qui changent rarement plutôt que de les redemander.

Ne pas perdre de données

Une requête refusée doit être réessayée plus tard ou envoyée dans la file d’exceptions, jamais ignorée.

Anticiper la croissance

Une automatisation qui fonctionne avec 50 éléments par jour peut atteindre les limites à 500. Estimez votre volume futur et vérifiez les quotas correspondants avant qu’ils ne deviennent un problème. Voir aussi surveiller une automatisation.
